# v6.4.0 "Anselmo"

Co-bonds made easy. No consensus change: a node on v6.2.0 or later follows the
same chain, and needs no upgrade for the switch to Midstate Walk at block
**371,500**.

Midwimble lets each mining bond sign an even share of full-weight blocks, so
the bonds behind a pool decide how many of its MDW blocks count. A **co-bond**
is a bond someone locks on a pool's mining key. They keep the coin, which only
their recovery phrase can spend, and the pool's midwimble node signs with it.
Until now that took a mining key from the operator, a file sent back a day
later and a node restart, and nothing paid for the locked coin.

## For co-bonders (desktop)

- **Bonds → New bond → A pool** takes the pool's address, which defaults to
  `rpc.cypherpunk.gold/pool`. The wallet asks the pool for its mining key and
  terms, and shows what co-bonding gives: the MDW fee with this bond counted,
  and the share of the pool's fee that goes to co-bonders.
- Once the lock confirms, the wallet hands the bond in to the pool, with this
  wallet's MDW address for its rewards. The pool registers it, which takes
  about a day, and the bond's card follows its progress.
- A bare mining key still works, for pools that take co-bond files.

## For pool operators

- `/pool/api/co-bonds` publishes the pool's mining key, its terms and the
  co-bonds behind it, and takes hand-ins. The dashboard has a co-bond panel,
  and each MDW address page shows its co-bonds and fee.
- **`--co-bond-reward <percent>`:** that share of the pool's midwimble fee goes
  to the co-bonds signing for it, an even cut per bond, paid in the block.
- **`--co-bond-fee-cut <points>`:** each such co-bond takes that many points
  off its owner's own midwimble fee, down to zero.
- Both default to 0, and with neither set the payouts are exactly as before.
- A bond's reward address is set by its first hand-in, and only for a bond the
  node had never seen, so nobody can claim someone else's.
- The pool's midwimble node must run **midwimble v1.3.1-DIMEBAG** or later,
  which takes co-bonds while it runs and registers them itself through its
  `--midstate-rpc`. On an older node the pool says it takes no co-bonds, and
  `--co-bond` files work as before.
- See `pools.md`, section 5.
